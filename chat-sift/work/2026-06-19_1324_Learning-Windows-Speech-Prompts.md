[M3] AI (2026-06-19 13:24):
The best way is to **learn it as a small command vocabulary**, not as a giant list.

For modern Windows 11, focus on **Voice Access** rather than old “Windows Speech Recognition”. Voice Access lets you control the PC and dictate text using on-device speech recognition, and Microsoft says it works without an internet connection. citeturn649951search4 The older Speech Recognition route still exists, and Windows can be trained to recognise your voice via **Windows key + Ctrl + S**. citeturn649951search5

### Best learning route

Start with these five command groups:

| Task | Learn these first |
|---|---|
| Start/stop listening | “Voice access wake up”, “Voice access sleep” |
| Open/switch apps | “Open Chrome”, “Switch to Word”, “Show desktop” |
| Clicking things | “Click [button name]”, “Show numbers” |
| Text dictation | “Type…”, punctuation words, “delete that”, “select that” |
| Keyboard control | “Press Enter”, “Press Control C”, “Press Windows S” |

The single most useful command is usually:

**“Show numbers”**

That overlays numbers on clickable areas, then you just say the number. It avoids needing to remember exact button names.

### Practice routine

Do 10 minutes a day:

1. Open Notepad.
2. Dictate a short paragraph.
3. Practise correcting it: “select that”, “delete that”, “correct [word]”.
4. Open a browser by voice.
5. Use “show numbers” to click around.
6. Finish by opening/closing apps and pressing keyboard shortcuts by voice.

That gives you the real-world muscle memory quickly.

### Set it up properly

For Windows 11 Voice Access:

**Settings → Accessibility → Speech → Voice access**

For old Speech Recognition training:

**Windows key + Ctrl + S**, then follow the setup wizard. You can also retrain via **Control Panel → Ease of Access → Speech Recognition → Train your computer to better understand you**. citeturn649951search5

### Don’t try to memorise everything

Make yourself a small cheat sheet with only 20 commands. Keep it by the screen. Add commands only when you actually need them.

A good starter list:

```text
Voice access wake up
Voice access sleep
Open [app]
Switch to [app]
Close window
Show numbers
Click [name]
Press Enter
Press Tab
Press Escape
Press Control C
Press Control V
Scroll down
Scroll up
Select that
Delete that
Correct [word]
New line
New paragraph
Stop listening
```

Also, don’t confuse the three Windows voice features:

| Feature | Best for |
|---|---|
| **Voice Access** | Controlling the PC and dictating |
| **Voice Typing** | Quick dictation only, starts with Windows + H |
| **Windows Speech Recognition** | Older command/control system |

Microsoft’s FAQ says Voice Access is started from **Settings → Accessibility → Speech**, while Voice Typing starts with **Windows logo key + H** and only works when your cursor is in a text box. citeturn649951search10

For what you’re doing, think in **printed millimetres**, not pixels. Pixels only matter because they define the print resolution.

At **300 dpi**:

```text

1 pt ≈ 4.17 px
180 px bleed ≈ 15.2 mm
```

So their “Ultimate” file size:

```text
11811 × 5905 px at 300 dpi
≈ 1000 × 500 mm finished size
```

That is a very good size for a full command mat.

## Practical minimum text sizes

For a desk mat you’ll read while sitting at the desk, I’d use this:

| Use | Printed text height | Font size approx | Pixel height at 300 dpi |
|---|---:|---:|---:|
| Main middle commands | **5–7 mm** | 16–22 pt | 60–83 px |
| Section headings | **7–10 mm** | 22–30 pt | 83–118 px |
| Normal command list | **3–4 mm** | 9–12 pt | 35–47 px |
| Dense secondary list | **2.5–3 mm** | 7–9 pt | 30–35 px |
| Absolute minimum | **2 mm** | 6 pt-ish | 24 px |

For a desk mat, I would not go below **2.5 mm text height** for anything you actually expect to read regularly. You can physically print smaller, but it becomes “magnifying-glass territory”, especially on fabric.

## Character thickness / stroke thickness

This matters more than people realise. Thin text can vanish into the cloth texture.

For a dark mat with coloured text:

| Element | Minimum stroke thickness |
|---|---:|
| Fine divider lines | **0.3 mm minimum** |
| Text strokes | Aim for **0.25–0.35 mm+** |
| Important boxes/borders | **0.5–1.0 mm** |
| Icons/symbols | **0.5 mm+** |

At 300 dpi:

```text
0.25 mm ≈ 3 px
0.3 mm ≈ 3.5 px
0.5 mm ≈ 6 px
1.0 mm ≈ 12 px
```

So don’t use ultra-light fonts. Use **regular, medium, semi-bold, or bold**. For dense command lists, **Arial / Helvetica / Inter / Aptos / Roboto Condensed / Arial Narrow** would work. Avoid thin decorative fonts.

## Important warning: fabric print eats detail

A desk mat is not like glossy paper. The cloth weave softens small text. So something that looks sharp on your screen may print slightly fuzzy.

For that reason:

- Use **light text on dark background**, but not ultra-thin.
- Avoid tiny red-on-black or blue-on-black text.
- Use **bold/semi-bold** for coloured text.
- Keep line spacing generous: at least **110–130%**.
- Avoid putting text right up against coloured boxes.
- Do not rely on 1 px lines. They may disappear.

## Quick test before ordering

This is the best practical method:

1. Make a small test panel with text at **6 pt, 7 pt, 8 pt, 9 pt, 10 pt, 12 pt**.
2. Include normal, bold, and condensed fonts.
3. Print it on A4 at **actual size / 100% scale**.
4. Put it on your desk.
5. Sit normally and see what you can read without leaning in.

If 7 pt is readable on paper, assume it will be **worse on the mat**. So choose one size up for anything important.

## Best compromise for your mat

For an **Ultimate 1000 × 500 mm** mat, I’d design around:

```text
Canvas: 11811 × 5905 px
Keep safe text area inside: about 11450 × 5540 px
Main commands: 18 pt
Category headings: 14–16 pt
Normal list: 8.5–9.5 pt
Dense list: 7.5–8 pt
Minimum line thickness: 0.3 mm
Borders: 0.5 mm+
```

I’d avoid going below **7.5 pt** unless it is genuinely “bonus” reference text.

A sensible target would be: **150–250 commands readable**, rather than trying to cram in 500 and ending up with a beautiful but unusable mat.

Yes — **partly**, but not in the old “read a training script and it learns your voice” way.

With **Windows 11 Voice Access**, you can improve recognition mainly by:

1. **Correcting words as you dictate**
2. **Adding custom words to vocabulary**
3. **Using the interactive guide**
4. **Improving microphone input**

Microsoft’s current Voice Access guidance includes **“Add to vocabulary”**, which lets you add difficult names/terms and helps Voice Access recognise them more accurately in future dictation. You can use the command **“Add to Vocabulary”**. citeturn197653search16

So for your mat, I’d include a small “Correction / Training” box with commands like:

```text
Correct [word]
Correct that
Select that
Delete that
Add to Vocabulary
Spell that
```

The practical workflow is:

```text
Dictate sentence
Say: Correct [wrong word]
Choose the correct option
Or say: Add to Vocabulary
Then re-dictate/check it
```

For example, if it keeps hearing “Saab” wrong, you’d add **Saab** to vocabulary. Same for names, technical terms, project names, unusual spellings, etc.

What it **doesn’t** really do is old-style continuous voice training where you read passages and it builds a full personal acoustic profile. That was more associated with older Windows Speech Recognition. Voice Access is more modern: it relies on its speech model, vocabulary biasing, correction, context, and mic quality.

The big accuracy wins are usually:

```text
Use a decent headset mic
Keep the mic distance consistent
Add your technical words/names to vocabulary
Use “correct that” immediately after errors
Avoid ultra-fast speech
Use Voice Access rather than Win+H for full control
```

For your desk mat, I’d definitely include **Add to Vocabulary** and **Correct that** as key middle-zone commands, because they’re not just editing commands — they’re how you gradually make the system more usable for your own vocabulary.
