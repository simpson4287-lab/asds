# **PixiBurn**  
**Universal PoE-Powered FPGA Burn-In Platform for Imaging Modules**

**Author:** Chris Simpson  
**Project Type:** Independent Engineering System Project  
**Status:** Concept → Prototype → Deployment  
**Intended Legacy:** Departmental Qualification Infrastructure  

---

## 1. Purpose & Vision

PixiBurn is a universal, mission-grade burn-in and endurance testing platform designed to qualify CCD and imaging modules under prolonged thermal stress. The system replaces fragmented, module-specific burn-in electronics with a single, adaptable, network-native solution.

The core philosophy of PixiBurn is to **treat every imaging module as flight hardware** — stressing it early, deterministically, and repeatably, to ensure long-term reliability in deployment.

PixiBurn is intended to be:
- reusable across generations of modules
- scalable without redesign
- simple to deploy and operate
- robust enough to become a long-term departmental standard

---

## 2. Problem Statement

Current burn-in processes rely on:
- multiple bespoke burn-in modules
- duplicated electronics per device type
- manual configuration and monitoring
- limited reuse as designs evolve

This results in:
- increased engineering overhead
- longer qualification lead times
- higher risk of configuration error
- reduced consistency across endurance tests

There is a clear need for a **single, universal burn-in system** capable of servicing a wide variety of imaging modules without repeated redesign.

---

## 3. Project Objectives

### Primary Objectives
- Design a **one-shot universal burn-in electronics cage** capable of servicing nearly all CCD / imaging modules
- Provide deterministic, long-duration endurance testing under elevated temperature
- Replace multiple legacy burn-in electronics with a single platform

### Secondary Objectives
- Minimise cabling and infrastructure complexity
- Enable remote monitoring and control
- Ensure long-term maintainability and extensibility
- Create a system that can outlive its original designer

---

## 4. System Overview

PixiBurn consists of a **PoE-powered FPGA control node** integrated into a modular burn-in cage, installed within a thermal oven environment.

At a high level, PixiBurn provides:
- power delivery
- control sequencing
- data acquisition
- health monitoring
- networked supervision

All functionality is delivered through a **single Ethernet connection**, reducing complexity and increasing robustness.

---

## 5. Key Design Principles

1. **Universality**  
   One hardware platform, configurable through profiles rather than redesign.

2. **Network-Native**  
   Power, control, and telemetry delivered over Ethernet.

3. **Determinism**  
   FPGA-based control ensures repeatable, time-accurate behaviour.

4. **Modularity**  
   Mechanical and electrical interfaces allow adaptation to new modules.

5. **Mission-Grade Mindset**  
   Designed as if qualifying space-bound imaging payloads.

---

## 6. System Architecture

### 6.1 PixiBurn Node
The PixiBurn Node is the core unit and consists of:
- FPGA (primary control and sequencing)
- PoE PD interface
- power regulation and protection
- configurable I/O interfaces
- temperature and health monitoring

Each Node is capable of:
- controlling one or more burn-in modules
- operating autonomously once configured
- reporting status continuously over Ethernet

---

### 6.2 Burn-In Cage
- Mechanical enclosure supporting multiple module adapters
- Designed for oven compatibility
- Passive where possible to maximise reliability
- Supports airflow and thermal stability

---

### 6.3 Module Interface Adapters
- Simple, replaceable interface boards
- Translate PixiBurn Node I/O to specific module pinouts
- Allow future module support without core redesign

---

## 7. Power Architecture

- Primary power delivered via **Power over Ethernet (PoE)**
- Eliminates separate power cabling into the oven
- Power budget sized for:
  - FPGA operation
  - module biasing and control
  - monitoring circuitry
- Local regulation and protection per Node

---

## 8. Control & Firmware

### FPGA Responsibilities
- burn-in sequencing
- bias generation control
- timing and clock management
- fault detection
- watchdog and safety interlocks

### Configuration Model
- Module-specific behaviour defined by **Burn-In Profiles**
- Profiles determine:
  - voltage levels
  - sequencing order
  - timing
  - duration
  - safety limits

Profiles can be updated without hardware changes.

---

## 9. Communications & Monitoring

- Ethernet-based control and telemetry
- Remote status reporting:
  - voltages
  - currents
  - temperatures
  - fault states
- Designed to integrate with:
  - simple GUIs
  - logging systems
  - automated test frameworks

---

## 10. Safety & Reliability Considerations

- Power limiting and current monitoring
- FPGA-enforced safe-state defaults
- Thermal monitoring with shutdown thresholds
- Fail-safe behaviour on network or power loss
- No single point of failure within the oven environment

---

## 11. Scalability & Future Expansion

PixiBurn is explicitly designed to scale:
- multiple Nodes per oven
- multiple ovens per network
- future FPGA upgrades
- support for non-CCD imaging modules

The architecture avoids assumptions that would limit future applicability.

# **Slide 2 — Background & Context**

- CCD and imaging modules require prolonged thermal endurance testing (“burn-in”) prior to deployment  
- Burn-in is a critical reliability gate, not a formality  
- The number and diversity of imaging modules is increasing  
- Qualification expectations are becoming more stringent over time

---

# **Slide 3 — Current Burn-In Approach**

- Burn-in performed using multiple bespoke electronics modules  
- Each imaging module typically requires a dedicated burn-in design  
- Hardware is tightly coupled to a specific device generation  
- Reuse across projects is limited

---

# **Slide 4 — Problems With the Current Approach**

- Repeated engineering effort for each new module  
- Long lead times before burn-in capability is available  
- Increased risk of configuration or handling errors  
- Inconsistent endurance testing between module types  
- Legacy burn-in hardware becomes obsolete quickly

---

# **Slide 5 — Why This Problem Is Growing**

- Increasing variation in module form factors and interfaces  
- Shorter development cycles  
- Higher expectations for unattended and repeatable testing  
- Burn-in complexity increases with module sophistication  
- Existing approach does not scale

---

# **Slide 6 — What “Good” Looks Like**

A successful burn-in system should:

- Support multiple imaging modules without redesign  
- Minimise cabling and infrastructure inside the oven  
- Provide deterministic, repeatable control  
- Operate unattended for long durations  
- Be maintainable and extensible long-term

---

# **Slide 7 — Proposed Concept: PixiBurn**

PixiBurn is a **universal burn-in platform** consisting of:

- A PoE-powered FPGA control node  
- A modular burn-in cage suitable for oven use  
- Configurable interfaces for different imaging modules  
- Network-based control and monitoring

---

# **Slide 8 — Why This Architecture**

**Power over Ethernet (PoE):**
- Single cable for power and data  
- Simplifies oven integration  
- Reduces failure points

**FPGA-Based Control:**
- Deterministic sequencing and timing  
- Long-duration stability  
- Hardware-enforced safety behaviour

- Ethernet / PoE from external network  
- PixiBurn Node located within oven
