[M2] AI (2026-02-27 10:30):
No — they **don’t have to be that long**, but **they do have to be unique** once Altium compiles the multi-channel design.

What you’re seeing (e.g. `R17_CLK2`, `C1_CLK2`) is Altium making the designators unique by **appending the channel identifier** (often taken straight from the **Sheet Symbol / Channel Designator**, which in your case looks like `CLK2`).

### What you can do instead

#### 1) Keep the suffix, but make it short
If your repeated channel designators are named `CLK2`, `CLK3`, etc., Altium will happily glue that onto every part designator.

So the simplest fix is: **rename the channel designators** to something short like `1`, `2`, `3` (or `A`, `B`, `C`).  
Then you get `R17_2` / `R17_B` instead of `R17_CLK2`.

Where: on the **Sheet Symbol** that instantiates the channel (the “child sheet” symbol), edit its **Designator / Channel Designator** field.

#### 2) Don’t append the channel at all (only if you don’t need uniqueness at that level)
In Altium, the PCB and outputs generally expect **unique component designators**. If you turn off suffixing, you’ll typically end up with **duplicate `R17` across channels**, which breaks ECO/back-annotation/BOM uniqueness.

So you *can* disable suffixing in some annotation schemes, but it’s usually a dead end unless you’re doing something very custom.

#### 3) Keep PCB designators short, show the channel elsewhere
A common “best of both” approach is:

- Keep `R17_CLK2` as the *true unique designator* (so Altium stays sane)
- Put **channel** on assembly/schematic documentation as a **separate parameter** (e.g. `CHAN=CLK2`) or use the **hierarchical path** in BOM/outputs
- On PCB silkscreen/assembly, display a **shortened string** if needed (e.g. just `R17`) and show channel in assembly notes/variant/BOM

This keeps manufacturing readable without fighting Altium’s uniqueness rules.

### Multi-channel propagates **schematic** changes automatically, not PCB routing
In Altium, a multi-channel design means:

- **Schematic**: one child sheet → compiled into N channels (CLK1/CLK2/…); edit the child sheet and all channels update on **Compile + ECO**.
- **PCB**: each channel becomes a **different set of components/nets**, so **routing is not “the same object”** across channels. Changing a track in one channel **does not automatically rewrite** the others.

So your impression (“change a track in master and it propagates”) is true in some tools / flows, but in Altium it only happens if you use **Rooms + replication commands**, or if you deliberately copy/paste routing between rooms.

## Common gotchas (why it “doesn’t propagate”)

1) **You don’t actually have rooms**, so there’s nothing to replicate.

4) You edited routing **outside the room boundary**, so replication ignores it.
5) You updated the PCB from schematic and the ECO **recreated rooms**, breaking earlier assumptions.

In Altium you “declare” board thickness in **two places**, depending on what you need it to drive.

## 1) For fabrication output and stackup (the real answer)
**Design → Layer Stack Manager**  
1. Open **Layer Stack Manager**.
2. In the stack table, set the **dielectric/core/prepreg thicknesses** (and copper weights).
3. The **Total Thickness** is shown at the top (or in a “Total” row) — that’s the value fabs care about.
4. Save/close.

This is the authoritative thickness used for:
- stackup tables / fab drawings
- impedance calculations (if you use them)
- outputs that reference stack information

## 2) For 3D / enclosure clearance (MCAD-style)
**Design → Board Shape → Define Stackup / Board Thickness** (older flows vary)  
In AD26, it’s still best to use **Layer Stack Manager**, but if you’re just trying to make 3D look correct, ensure:
- your **Top/Bottom soldermask** and **paste** layers are defined in the stack if you want them included
- 3D body heights reference the correct datum (Top or Bottom)
